# CONSTITUTION — Тендер-радар

> Роль: Architect. Незыблемые правила проекта: стандарты качества, что разрешено/запрещено, дисциплина исполнения.

## 1. Технологические инварианты

- **Фронт:** Next.js (App Router) + TypeScript (strict, без `any`). UI — простой, без избыточной сложности.
- **БД бизнес-данных:** Supabase Postgres. Все пользовательские данные — под RLS.
- **Движок автоматизации:** N8N self-hosted. Бизнес-логика интеграций — в воркфлоу, НЕ во фронте.
- **Воркфлоу = код:** каждый N8N-воркфлоу экспортируется в `n8n/workflows/*.json` и коммитится. UI N8N не является источником истины.

## 2. Стандарты качества кода

- Junior-level ясность: простая и явная логика. **Без наследования, рефлексии, сложного метапрограммирования.**
- DRY, YAGNI. Не реализуем то, чего нет в текущей фазе.
- TypeScript strict; типы на границах (Supabase-типы генерируются из схемы).
- Code-ноды N8N (JS/Python) — короткие, с понятными именами, без скрытых side-effect.
- Никаких секретов в коде/воркфлоу/git. Только `.env` + credential store. `.env.example` обязателен.

## 3. Дисциплина исполнения (phase isolation)

- Разработчик исполняет **только активную фазу** из IMPLEMENTATION_PLAN.md.
- Запрещено тянуть задачи из будущих фаз. Нужное, но «не из этой фазы» → `Deferred to Phase N: <причина>` в `docs/tech-debt-tracker.md` + `HANDOFF.md`.
- Один логический change = один коммит (атомарные коммиты). Не смешивать фазы в одном коммите.
- Коммит после каждого завершённого шага/гейта.

## 4. Верификация (verification over vibes)

- «Работает» без доказательства не принимается. Каждая фаза определяет команды и наблюдаемые критерии.
- Блокирующие проверки должны возвращать exit code 0:
  - `npm run build`, `npm run lint`, `tsc --noEmit`, `npm test` (фронт).
  - N8N-воркфлоу: ручной прогон с реальным/мок-входом, проверка вход/выход каждой ноды, запись в БД подтверждена.
- Любой non-zero exit на блокирующей проверке = FAIL, проход через гейт запрещён.

## 5. Устойчивость и безопасность (обязательно)

- На каждом внешнем вызове (ЕИС, каналы) — `Retry On Fail` + backoff.
- Глобальный Error Workflow ловит сбои и алертит.
- Идемпотентность: повторная загрузка не плодит дубликаты (`reg_number+version`).
- Сбой одного канала уведомлений не блокирует другие.
- Вебхуки защищены секретом/Header Auth.

## 6. Документация и навигация

- `PROJECT_INDEX.md` всегда отражает реальную структуру.
- Длинные документы разбиваются на родитель-summary + дочерние (`docs/`), без молчаливого изменения смысла.
- Отложенная работа фиксируется в `docs/tech-debt-tracker.md`, не прячется.

## 7. Запрещено

- Перепродажа N8N как хостинг/SaaS (лицензия fair-code).
- Telegram как **единственный** канал (нестабилен в РФ) — только как демо/доп.
- Секреты в git.
- Реализация будущих фаз без явного разрешения плана.
- Изменение смысла канонических артефактов при рефакторинге документации.

## 8. Определение Done (общее)

Фаза завершена, когда: код написан в пределах скоупа фазы, все verification-команды зелёные, PROGRESS.md и HANDOFF.md обновлены, отложенное записано в tech-debt-tracker, оба ревью (SOLID + SRE) одобрены.
