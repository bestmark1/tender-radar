# PRD — Тендер-радар (Product Requirements Document)

> Роль: Product PM. User stories, критерии приёмки, метрики успеха, out-of-scope.

## 1. Обзор

Веб-сервис, который автоматически забирает свежие закупки 44-ФЗ/223-ФЗ из ЕИС, фильтрует их по правилам пользователя и присылает подборку с дедлайнами (email + VK), отображая всё в дашборде с календарём сроков. Движок обработки — N8N (self-hosted).

**Объём MVP:** регион **Москва (77) + Московская область (50)**, вертикаль **клининг/уборка (ОКПД2 81.2)**, 1 пользователь (пилот). LLM-скоринг и CRM-интеграция — за пределами MVP (Фаза 2).

**Каналы уведомлений MVP:** email (SMTP), VK, MAX, Telegram. Telegram — прежде всего быстрый **демо-канал** (нативная нода N8N); продукт не зависит от него. MAX — через HTTP Request к MAX Bot API (нативной ноды нет; при недоступности API → Фаза 2).

## 2. Пользовательские роли (MVP)

- **Поставщик (единственная роль MVP):** настраивает «радары» (правила), получает уведомления, смотрит дашборд. Мультиарендность и роли — Фаза 2.

## 3. User Stories и критерии приёмки

### US-1 — Настройка «радара» (правил мониторинга)
**Как** поставщик, **я хочу** задать правила (регион(ы), ОКПД2, ключевые слова, мин/макс сумма, закон 44/223), **чтобы** получать только релевантные закупки.

**Критерии приёмки:**
- AC-1.1: Можно создать «радар» с полями: название, список регионов (код), список ОКПД2 (префиксы), ключевые слова (include/exclude), диапазон НМЦК (мин/макс), закон (44/223/оба).
- AC-1.2: Радар сохраняется в БД и доступен для редактирования/удаления.
- AC-1.3: Можно включить/выключить радар без удаления.
- AC-1.4: Валидация: нельзя сохранить радар без хотя бы одного региона и одного критерия фильтрации.

### US-2 — Автоматическая загрузка закупок из ЕИС
**Как** система, **я хочу** по расписанию забирать свежие документы из ЕИС по регионам активных радаров, **чтобы** иметь актуальные данные.

**Критерии приёмки:**
- AC-2.1: N8N-воркфлоу по расписанию (1–2 раза/день) вызывает SOAP `getDocsByOrgRegionRequest` с токеном для каждого нужного региона + типа документа (notification) за период с прошлого запуска.
- AC-2.2: Полученная ссылка на архив скачивается с токеном, ZIP распаковывается, XML парсятся.
- AC-2.3: Каждая закупка нормализуется в запись: реестровый номер, наименование, заказчик, регион, ОКПД2, НМЦК, дата публикации, дата окончания подачи, ссылка на ЕИС.
- AC-2.4: Идемпотентность: повторная загрузка той же закупки не создаёт дубликат (upsert по реестровому номеру + версия).
- AC-2.5: Ошибки загрузки/парсинга ловятся Error Workflow и логируются; запуск не падает целиком из-за одного битого документа.

### US-3 — Фильтрация по правилам радара
**Как** система, **я хочу** сопоставлять загруженные закупки с правилами радаров, **чтобы** отбирать релевантные.

**Критерии приёмки:**
- AC-3.1: Для каждой новой закупки проверяются все активные радары; совпадение фиксируется (закупка ↔ радар).
- AC-3.2: Фильтр учитывает: регион, префикс ОКПД2, include/exclude ключевые слова (по наименованию), диапазон НМЦК, закон.
- AC-3.3: Одна закупка может совпасть с несколькими радарами; в подборку пользователю она попадает один раз с пометкой совпавших радаров.
- AC-3.4: Уже отправленные ранее совпадения повторно не уведомляются.

### US-4 — Уведомления (email + VK + MAX + Telegram)
**Как** поставщик, **я хочу** получать подборку новых релевантных закупок и напоминания о дедлайнах, **чтобы** не пропустить подачу.

**Критерии приёмки:**
- AC-4.1: После цикла фильтрации формируется дайджест новых совпадений и отправляется по включённым каналам (email SMTP, VK, MAX, Telegram — по настройке пользователя). Telegram доступен как демо-канал; MAX — через HTTP Request к MAX Bot API.
- AC-4.2: Дайджест содержит по каждой закупке: наименование, заказчик, НМЦК, дату окончания подачи, ссылку на ЕИС, совпавший радар.
- AC-4.3: Если новых совпадений нет — пустой дайджест не отправляется.
- AC-4.4: Напоминание о дедлайне: за N дней (настраиваемо, по умолчанию 2) до даты окончания подачи по закупкам, помеченным пользователем как «интересно», отправляется отдельное уведомление.
- AC-4.5: Доставка уведомлений устойчива к сбоям (ретраи); сбой одного канала не блокирует другой.

### US-5 — Дашборд и календарь дедлайнов
**Как** поставщик, **я хочу** видеть найденные закупки и сроки в веб-интерфейсе, **чтобы** управлять ими.

**Критерии приёмки:**
- AC-5.1: Список найденных закупок с фильтрами (по радару, статусу, дате окончания), сортировкой по дедлайну.
- AC-5.2: По каждой закупке — карточка с полями из AC-2.3 и ссылкой на ЕИС.
- AC-5.3: Пользователь может пометить закупку: «интересно» / «скрыть».
- AC-5.4: Календарь/таймлайн дедлайнов подачи по отмеченным «интересно».
- AC-5.5: Дашборд читает данные из Supabase (с обновлением, близким к реальному времени).

### US-6 — Защита и устойчивость (нефункциональные, но проверяемые)
**Критерии приёмки:**
- AC-6.1: Вебхуки N8N защищены секретом/подписью; неавторизованный запрос отклоняется.
- AC-6.2: Токен ЕИС и секреты хранятся вне репозитория (env/credential store), не в git.
- AC-6.3: Есть Error Workflow с уведомлением администратора о сбоях.
- AC-6.4: Воркфлоу экспортируются в JSON и версионируются в git.
- AC-6.5: N8N развёрнут в Docker (docker-compose: n8n + Postgres + Redis), queue mode.

## 4. Метрики успеха

- **Функциональные:** все AC выше проходят (трассируются в QA-фазе).
- **Портфолио:** README со схемой + GIF воркфлоу; все «галочки» low-code (AC-6.x) присутствуют.
- **Продуктовые гипотезы (пилот):** релевантность ≥ 70%; 0 пропущенных дедлайнов; задержка уведомления < 24 ч.

## 5. Out of scope (MVP)

- Подача заявок, работа с ЭТП, ЭЦП-подписание.
- LLM-скоринг релевантности (→ Фаза 2).
- Интеграция с Битрикс24/amoCRM (→ Фаза 2).
- Мультиарендность, роли, биллинг/подписки.
- Все регионы и полный ОКПД2 (MVP — узкий скоуп; MVP = Москва + МО).
- Аналитика конкурентов, история цен, прогнозы.
- Мобильное приложение.

## 6. Зависимости и допущения

- **Задача 0 (вне кода, блокирующая):** получить токен потребителя машиночитаемых данных на Госуслугах (физлицо/ИП). Без него US-2 не реализуема.
- Доступность SOAP-сервисов ЕИС и стабильность XSD-схем.
- Бесплатные тарифы Vercel, Supabase, VK API; дешёвый VPS под N8N.
- Fallback на сторонний JSON-API (DaMIA/GosPlan) допустим для разработки/демо, если SOAP заблокирует прогресс (фиксируется как tech-debt).
