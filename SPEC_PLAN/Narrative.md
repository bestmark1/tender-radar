# Narrative — Тендер-радар

> Роль: Narrative Lead. Источник истины для смысла продукта: история, «почему сейчас», мир пользователя, ключевые ограничения, не-цели, риски.

## 1. История продукта

Тысячи российских компаний-поставщиков живут за счёт госзаказа (44-ФЗ) и закупок госкомпаний (223-ФЗ). Но чтобы получить контракт, его сначала нужно **найти вовремя** — до истечения срока подачи заявки. Сегодня это делается одним из трёх способов:

1. **Вручную** — менеджер каждый день заходит на zakupki.gov.ru, листает выдачу, копирует интересное в Excel. Медленно, выматывает, пропуски неизбежны.
2. **Дорогие агрегаторы** (Контур.Закупки, СБИС, Тендерплан) — 15 000–50 000 ₽/мес. Для микро- и малого бизнеса это заметная статья расходов, а гибкость правил ограничена чужим интерфейсом.
3. **Никак** — узнают о тендере, когда уже поздно.

«Тендер-радар» — это лёгкий веб-сервис, который **сам** забирает свежие закупки из ЕИС, фильтрует их по правилам конкретного поставщика (регион, ОКПД2, ключевые слова, сумма), и присылает аккуратную подборку с дедлайнами на почту/VK, плюс показывает их в дашборде с календарём сроков. Ядро — низкокодовый движок N8N, который оркеструет загрузку, распаковку, парсинг и рассылку.

## 2. Почему сейчас (Why now)

- **Закрытие FTP ЕИС с 01.01.2025** сломало привычные самописные парсеры — порог входа для интеграции вырос (SOAP + токен), и часть мелких самоделок отвалилась. Появилось окно для нового аккуратного решения.
- **Уход западного SaaS/iPaaS** (Zapier, Make-облако, Slack/Trello) из РФ-контура → спрос на self-hosted автоматизацию внутри страны вырос.
- **Импортозамещение и требование хранить данные в РФ** делают self-hosted N8N естественным выбором.
- **Рынок труда:** в вакансиях массово просят опыт low-code/N8N-автоматизации, а у разработчика портфолио только на Python. Нужен первый сильный N8N-кейс, желательно на реальной, «денежной» B2B-задаче.
- **Доступ к данным остался бесплатным для физлица/ИП:** токен потребителя машиночитаемых данных выдаётся через Госуслуги без ЭЦП и юрлица — значит продукт можно построить и протестировать в одиночку.

## 3. Мир пользователя / операционный контекст

**Кто:** тендерный менеджер или собственник микро/малого бизнеса-поставщика. Часто это 1–3 человека, которые совмещают поиск тендеров с подготовкой заявок и основной работой.

**Их день:** утром нужно понять, появились ли новые подходящие закупки, не горит ли где дедлайн подачи. Решение «участвовать / пропустить» принимается за минуты. Цена ошибки — упущенный контракт (сотни тысяч — миллионы ₽) либо потраченное время на нерелевантные закупки.

**Каналы:** основные для пользователя — почта, VK и MAX (национальный мессенджер). Telegram в РФ нестабилен, поэтому он добавляется как **демо-канал** (эффектно показывается в N8N), но продукт от него не зависит. Часть пользователей ведёт воронку в CRM (Битрикс24/amoCRM) — но не все.

**Технический контекст:** у пользователя нет 1С/банковского API/ЭЦП в обязательном порядке. Сервис не должен требовать ничего из этого для базовой ценности.

## 4. Ключевые ограничения

- **Источник данных:** только SOAP-сервисы отдачи ЕИС (`int44.zakupki.gov.ru/eis-integration/services/getDocsIP`), токен в заголовке `individualPerson_token`. FTP недоступен. Ответ — ссылка на ZIP-архив XML, который качается тем же токеном.
- **Объём данных:** `getDocsByOrgRegionRequest` отдаёт документы пачками по региону + типу документа за период, а не «поиск по ключевому слову». Фильтрация (ОКПД2, ключевые слова, сумма) — **на нашей стороне**. → MVP ограничить 1–2 регионами и узким набором ОКПД2.
- **Лицензия N8N** (Sustainable Use License, fair-code): self-host для собственного/клиентского использования — ок; перепродажа «N8N-as-a-service» — нет.
- **Команда:** один разработчик (Python-бэкграунд, осваивает N8N). Веб-часть — тонкий слой.
- **Бюджет:** минимальный. Vercel/Supabase/VK — бесплатные тарифы; VPS под N8N — дешёвый (Selectel/Timeweb).
- **Каналы уведомлений:** email + VK + MAX (основные) + Telegram (демо-канал). Регион MVP: Москва (77) + Московская область (50). Вертикаль пилота: клининг/уборка (ОКПД2 81.2).

## 5. Не-цели (Non-goals)

- **Не** делаем подачу заявок/участие в торгах — только обнаружение и уведомление.
- **Не** делаем ЭЦП-подписание и работу с электронными площадками (ЭТП) в MVP.
- **Не** покрываем все регионы и весь ОКПД2 в MVP — узкая вертикаль.
- **Не** строим аналитику конкурентов/прогноз цен в MVP (возможная Фаза 3+).
- **Не** перепродаём N8N как хостинг.

## 6. Очевидные риски и допущения

| # | Риск / допущение | Влияние | Реакция |
|---|---|---|---|
| R1 | Токен ЕИС выдаётся физлицу/ИП без ЭЦП — допущение по статьям, не проверено лично | Высокое (блокер источника) | Задача 0: зарегистрировать токен на Госуслугах до начала кода. Fallback — сторонний JSON-API (DaMIA/GosPlan) для демо |
| R2 | SOAP-схемы ЕИС сложны, XSD меняются | Среднее | Зафиксировать версию схем, тесты парсинга на реальных архивах, Error Workflow |
| R3 | Объём данных по региону велик → долгая обработка | Среднее | queue mode + Redis, инкрементальная загрузка по периодам, узкий MVP-скоуп |
| R4 | Rate limits / блокировка при частых запросах к ЕИС | Среднее | Расписание (1–2 раза/день), ретраи с backoff, идемпотентность по реестровому номеру |
| R5 | Конкуренция с Контур/СБИС/Тендерплан | Среднее (продукт), низкое (портфолио) | Позиционирование: дёшево + гибкие правила + self-hosted; для портфолио конкуренция неважна |
| R6 | Лицензия N8N при будущей монетизации как SaaS | Низкое сейчас | Для MVP/портфолио — ок; при монетизации пересмотреть модель |
| R7 | Дедупликация: один тендер приходит в нескольких архивах/обновлениях | Среднее | Ключ идемпотентности = реестровый номер + версия, upsert в Postgres |
| R8 | MAX Bot API: зрелость/доступность не проверена, нативной ноды N8N нет | Среднее | Интеграция через HTTP Request; если API недоступен/нестабилен → MAX в Фазу 2, не блокирует MVP |
| R9 | Москва+МО — крупнейший по объёму регион, тяжёлая загрузка | Среднее | Жёсткое сужение по ОКПД2, инкрементальная загрузка по периодам, queue mode |

## 7. Определение успеха (на уровне истории)

- **Портфолио:** развёрнутый self-hosted N8N (Docker, queue mode, Error Workflow, sub-workflows, защищённые вебхуки, версионирование воркфлоу в git) + веб-дашборд + README со схемой и метрикой. Закрывает требования вакансий по low-code/N8N.
- **Продукт:** поставщик из выбранной вертикали получает ежедневную подборку релевантных закупок и ни разу не пропускает дедлайн подачи по своим правилам.
